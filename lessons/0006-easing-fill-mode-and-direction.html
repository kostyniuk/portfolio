Control How Motion Feels

Skill: read the animation shorthand as name, duration, easing, iteration, direction, and fill mode.

The Problem This Solves

Keyframes define what happens, but two animations with identical keyframes can feel completely different. Three recurring problems live in the gap:

Robotic motion. Nothing in the physical world moves at constant speed — things accelerate and decelerate. Motion that ignores this reads as cheap and mechanical, even when the user can't say why.

The flash of un-animated state. Animation styles only apply while the animation is active. An element with a 400ms delay spends those 400ms in its plain CSS state — so a fade-in element appears at full opacity, blinks away, then fades in. This bug is almost invisible in code and glaring on screen.

The loop snap. A repeating animation jumps from its last frame straight back to its first, producing a visible stutter every cycle.

Each has a dedicated knob: animation-timing-function, animation-fill-mode, and animation-direction.

Easing: Same Keyframes, Different Feel

The timing function reshapes how progress is distributed across the duration. Both dots below travel identical keyframes for identical durations — the top one linearly, the bottom one with a curve that starts fast and lands softly. Watch which one feels like an object and which feels like a printer head.

.dot {
  animation: travel 1.8s infinite alternate both;
}
.linear { animation-timing-function: linear; }
.ease   { animation-timing-function: cubic-bezier(.16, 1, .3, 1); }

For UI work the default desire is almost always ease-out (fast start, soft landing): the interface feels responsive because motion begins instantly, and calm because it never slams to a stop. Save linear for progress bars and spinners, where constant speed is the honest signal.

Fill Mode And Direction: The Edges Of Playback

animation-fill-mode answers "what styles apply outside active playback?" — backwards applies the first keyframe during a delay (killing the flash described above), forwards keeps the last keyframe after the animation ends (so a fade-in doesn't pop back to its plain style), and both does both. This is why your sibling-index stagger needs both: every item except the first has a delay, and without fill mode each one would flash visible before its turn.

animation-direction: alternate answers the loop snap: play forward, then play backward, so the cycle is seamless. The dots above use it — that's why they sweep back instead of teleporting to the start.

On Your Portfolio

These three knobs are the difference between "has animations" and "feels designed." Every staggered reveal you build from here on should ship with an ease-out curve and animation-fill-mode: both as the default starting point.
