# x.ai Hero Effect Teardown

The learner asked to learn the animated headline on x.ai ("Frontier AI models for everything you …"). The live site is Cloudflare-protected (403 to fetch); the markup was recovered from a Wayback Machine snapshot (June 2026).

The effect is **three independent techniques**, now taught as a trio (Lessons 0012–0014):

1. **Per-word 3D flip-up reveal** (Lesson 0012). `<h1 style="perspective:1200px">` with each word in a `display:inline-block` span animating from `opacity:0; translateY(45%) rotateX(-40deg)` to upright. New primitive vs. the rest of the series: `perspective` (on the parent) + `rotateX`. Stagger reuses `sibling-index()` (Lesson 1); self-start reuses keyframes (Lesson 5).
2. **Gradient shimmer underline** (Lesson 0013). An absolutely-positioned `h-[3px]` bar that (a) grows in via `scaleX(0)→1` with `transform-origin:left`, and (b) has a mostly-grey gradient with a rainbow band (`#6366f1 #a855f7 #ec4899 #f97316 #eab308`) in the middle, `background-size:400%`, with `background-position` animated so the colour "slips" across once. The learner described this precisely before the markup confirmed it ("grey, a shot of colour, grey again, like a progress bar").

3. **Rotating last word** (Lesson 0014). The underlined word swaps to a new word every ~2s. The snapshot tell is the underlined word rendered as a stacked outgoing/incoming pair (`<span>build</span><span>build</span>`); the actual word list lives in the client JS bundle, not the static HTML. Rebuilt as a pure-CSS vertical reel: a fixed-height `overflow:hidden` slot over a column of word spans, a stepped `@keyframes` `translateY` (equal-percentage pairs = the ~2s dwell), with the first word duplicated at the end for a seamless loop. New idea introduced: a multi-step keyframe is a timeline through N states.

Key teaching insight: x.ai drives all three with JS (framer-motion, single `hero-shimmer` keyframe, data-driven word list). The static versions were rebuilt in **pure CSS** to match the mission's "no JS for simple timing" goal — with the honest boundary that the rotating word goes to JS when the list is data-driven or needs per-item enter/exit. The learner spotted both the underline's progress-bar behaviour and the word rotation before the markup confirmed them — strong observational read of a live site.

**Capstone (Lesson 0015) + shipped component.** The learner then identified the two genuinely dynamic behaviours x.ai's JS adds: the underline **resizes per word** (needs runtime text measurement) and the shimmer **replays on every swap** (needs re-trigger on a discrete event). This crystallised the CSS-vs-JS boundary: CSS owns *timing*, JS owns *orchestration* (reacting to changing state / measured layout). We then shipped it as a real component — `components/animated-headline.tsx` (Motion-based: `layout` for resize, `AnimatePresence` + keyed remount for the replaying shimmer, `useReducedMotion` guard) — live in the About hero ("Engineering things people love to build/design/ship/use") and demoed on `/my-components`. Typecheck + lint clean; both pages render 200. The learner has now gone full circle: observe a live effect → decompose into primitives → rebuild static (CSS) → rebuild dynamic (JS) → ship to production. Strong anchor for future "reverse-engineer this site" sessions.
