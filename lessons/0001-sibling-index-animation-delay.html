Stagger With sibling-index()

Tiny win: make sibling elements animate one after another by deriving each delay from its DOM position.

Progressive Enhancement

This lesson uses sibling-index() directly, so the CSS can derive each item’s place without repeated index rules.

The Problem This Solves

A staggered reveal needs each item to start a little later than the one before it — which means each item needs to know its own position. CSS had no way to ask "which child am I?", so every workaround smuggled the index in from outside: a ladder of per-item rules (.item:nth-child(2) { animation-delay: 120ms; }, :nth-child(3) { ... }, and so on), an SCSS @for loop generating that same ladder at build time, or JavaScript injecting a custom property per element (style={{ "--i": index }} in React).

All three share the same failure: the timing is welded to a fixed item count. Add a fifth stat to a four-item list and the ladder is wrong, the loop needs a rebuild, or the component needs JS it otherwise wouldn't. The desire behind sibling-index() is simply: let the stylesheet read the DOM position itself, so one rule covers any number of items.

The One Idea

sibling-index() returns an integer for the current element's position among its siblings. The first child returns 1, so subtract 1 when you want the first item to start immediately.

delay = (sibling-index() - 1) x step 
.item {
  --step: 120ms;
  animation-delay:
    calc((sibling-index() - 1) * var(--step));
}

Boundaries: When Is It Enough?

sibling-index() is new, so the mission question — when is it enough, when do you need a fallback — has a clean answer rooted in how it fails. In a browser that doesn't support it, the calc() is invalid, the delay resolves to 0ms, and all items animate together: no stagger, but nothing breaks and the content shows. For decorative motion on a portfolio, that degradation is acceptable and no fallback is needed.

Reach for the old JS-injected --i only when the index drives something users would miss, not just motion polish. Keep the markup plain and let CSS derive the index — the content stands on its own; the stagger is the enhancement.
