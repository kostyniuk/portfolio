Rotate Appearance Is a Wrapper

Skill: package a 3D flip-up entrance as a reusable wrapper while keeping the stagger decision outside the child content.

The problem it solves

A headline reveal is made of repeated entrance animations. If every word owns its own timing, the code becomes a pile of almost-identical spans. If the parent owns all timing, the child can become too magical to reuse elsewhere.

The important discovery: this particular effect does not need Motion. CSS can do the reveal cleanly once every word is wrapped in its own element. RotateAppearance is useful only if you want a React component API for that wrapper.

The idea

The effect has two jobs. First, make each word into a transformable box. Second, run the same flip-up keyframe on every word, with a delay derived from each word's sibling position.

CSS can own both jobs if the markup is shaped correctly. The browser already knows the DOM order, and sibling-index() can read that order for direct element siblings. No React state, measurement, or exit lifecycle is needed for this entrance reveal.

The required markup

CSS cannot animate raw words separately inside a plain text node. This does not give CSS four things to count:

<h1 class="headline">Frontier models for builders</h1>

This does, because each word is now an element sibling:

<h1 class="headline">
  <span class="word">Frontier</span>
  <span class="word">models</span>
  <span class="word">for</span>
  <span class="word">builders</span>
</h1>

sibling-index() counts those .word spans because they share the same parent. It does not count human-language words. So the lesson's first rule is: split the text into word elements before trying to stagger it.

Style by style

.headline { perspective: 1200px; }

rotateX() is a 3D transform. Perspective is the camera distance that makes the rotation read as depth instead of a flat squash. Put it on the parent so all words share the same camera.

.word { display: inline-block; }

A plain inline text run is not a reliable transform target. inline-block keeps the word flowing like text, but gives it its own box so translateY and rotateX can move it.

transform-origin: 50% 100%;

The first value is horizontal center. The second is vertical bottom. This makes each word flip up from its baseline area instead of rotating around its center.

animation: flip .72s cubic-bezier(...) both;

flip names the keyframes. .72s is the duration. The easing starts quickly and settles softly. both applies the first keyframe before the animation starts and keeps the last keyframe after it ends, avoiding a flash of the final style before delayed words animate.

animation-delay: calc((sibling-index() - 1) * 110ms);

sibling-index() is 1-based: first word is 1, second is 2. Subtracting 1 makes the first delay 0ms. Then every next word starts 110ms later.

The complete CSS

.headline {
  display: flex;
  flex-wrap: wrap;
  align-items: baseline;
  gap: 0.28em;
  perspective: 1200px;
}

.word {
  display: inline-block;
  transform-origin: 50% 100%;
  animation: flip 0.72s cubic-bezier(0.2, 0.72, 0.2, 1) both;
  animation-delay: calc((sibling-index() - 1) * 110ms);
}

@keyframes flip {
  from {
    opacity: 0;
    transform: translateY(45%) rotateX(-40deg);
  }

  to {
    opacity: 1;
    transform: translateY(0) rotateX(0);
  }
}

@media (prefers-reduced-motion: reduce) {
  .word {
    animation: none;
  }
}

What each keyframe value does

opacity: 0 to 1

The word fades in while it travels. Without opacity, the rotated word can be readable too early and look like it is sliding from nowhere.

translateY(45%) to 0

The word begins 45% of its own height below its final position. Percentages in transforms are based on the transformed element's own size, so this scales with the text size.

rotateX(-40deg) to 0

The word starts tilted backward around the X axis and settles flat. The parent perspective makes that tilt visible as a flip rather than a flat distortion.

How React can generate the same markup

If the headline text comes from a string prop, React can still split it into spans. That does not require Motion:

const prefixWords = prefix.trim().split(/\s+/).filter(Boolean);

Then render one .word span per word and let CSS handle the delay:

{prefixWords.map((word, index) => (
  <span
    key={`${word}-${index}`}
    className="word"
  >
    {word}
  </span>
))}

This is the best version when the reveal is just an entrance animation. React creates the word elements; CSS animates them.

If sibling-index() support is too new

The fallback is still CSS animation. React only provides the number as a CSS custom property:

{prefixWords.map((word, index) => (
  <span
    key={`${word}-${index}`}
    className="word"
    style={{ "--i": index + 1 }}
  >
    {word}
  </span>
))}

Then replace the delay line with:

.word {
  animation-delay: calc((var(--i) - 1) * 110ms);
}

The animation remains CSS-owned. The only difference is where the index comes from: the browser's sibling tree, or React's array index.

Optional Motion translation

If you already use Motion in the component, the same styles translate into Motion values. This is not necessary for this reveal; it is just the equivalent API shape:

<motion.span
  className="word"
  style={{ transformOrigin: "50% 100%" }}
  initial={{ opacity: 0, y: "45%", rotateX: -40 }}
  animate={{ opacity: 1, y: "0%", rotateX: 0 }}
  transition={{
    duration: 0.72,
    ease: [0.2, 0.72, 0.2, 1],
    delay: index * 0.11,
  }}
>
  {word}
</motion.span>

Notice that Motion still does not split the words. React still maps over prefixWords. The only difference is where the animation declarations live: CSS keyframes and sibling-index(), or Motion props and index * 0.11.

How the CSS runs

The browser parses the word spans.

Each .word is a direct child of .headline, so each one has its own sibling-index() value.

The animation delay is calculated per word.

The first word gets (1 - 1) * 110ms = 0ms. The second gets (2 - 1) * 110ms = 110ms. The third gets 220ms.

both prevents the delayed flash.

Before a delayed word starts, it holds the from keyframe: hidden, lowered, and rotated. After it finishes, it keeps the to keyframe.

The parent perspective makes the 3D feel shared.

All words rotate within the same parent camera, so the headline feels like one choreographed reveal rather than disconnected spins.

Reduced motion skips the journey.

The media query removes the animation entirely. The words render in their normal settled positions.

Boundaries

  • Use CSS for this reveal when each word can be rendered as a direct sibling element.
  • Use a fallback delay variable, like style={{ "--i": index + 1 }}, if sibling-index() support is not acceptable for the audience.
  • Use Motion only if this reveal needs to participate in a larger Motion choreography. The reveal itself does not require it.
  • Keep perspective on the parent when multiple children should share the same 3D space.
