Subdomain Routing

A subdomain route has two jobs: get the hostname to your deployment, then decide what page that hostname should render.

The Two Layers

DNS and Vercel

Make www.lovable.a13x.space resolve to the Vercel project. For a subdomain, Vercel asks for a CNAME record.

Next.js routing

Once the request reaches the app, use the request Host header to map / on that host to an internal page.

Pattern Used Here

async rewrites() {
  return {
    beforeFiles: [
      {
        source: "/",
        has: [
          {
            type: "host",
            value: "www\\.lovable\\.a13x\\.space(?::\\d+)?",
          },
        ],
        destination: "/lovable",
      },
    ],
  };
}

Why `beforeFiles`?

The normal portfolio homepage already exists at /. A beforeFiles rewrite can override that filesystem page for only the matching host. Because the source is exactly /, static assets such as /lovable/pulse.webp and /_next/* still pass through normally.

Local Test

npm run dev
curl -H "Host: www.lovable.a13x.space:3000" http://127.0.0.1:3000/

If you want to use a browser, add 127.0.0.1 www.lovable.a13x.space to /etc/hosts, then open http://www.lovable.a13x.space:3000/.

Deployment Checklist

  1. Add www.lovable.a13x.space to the Vercel project domains.
  2. Add the CNAME record Vercel requests at your DNS provider.
  3. Deploy the code containing the host rewrite.
  4. Visit https://www.lovable.a13x.space/ after DNS and SSL finish provisioning.
