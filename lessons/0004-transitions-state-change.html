Transitions Animate State Changes

Skill: define motion for a before-and-after state without writing keyframes.

The Problem This Solves

By default, every style change in CSS is instantaneous. A hover style, a class toggle, a theme switch — the browser snaps from old to new in a single frame. Snapping is jarring, and worse, it hides causality: when something teleports to a new state, the user can't see what changed or where it went.

Before transitions existed, the only fix was JavaScript: jQuery's .animate() running dozens of timer callbacks per second, recalculating styles on the main thread. Transitions were CSS's answer to a simple desire: "I already declared both states — browser, you fill in the in-between frames."

The Idea: Describe States, Not Motion

This is the key mental shift. With a transition you never describe movement. You describe two end states — the resting style and the hover style — and one extra line that says which properties are allowed to interpolate and how long it takes. The browser computes every intermediate frame.

That makes transitions reactive: they don't care what caused the change. The same transition line animates a hover, a class added by JavaScript, a media-query flip, or a theme change. One declaration covers every way the state can move, in both directions — hover off animates back for free.

.button {
  transition:
    transform 180ms ease,
    box-shadow 180ms ease;
}

.button:hover {
  transform: translateY(-3px);
  box-shadow: 0 12px 24px rgb(0 0 0 / .10);
}

Where Transitions Stop

The two-state model is also the limit. A transition can't loop, can't have a middle beat (down-then-up needs three states), can't start on its own (something must change), and can only animate properties whose values can be mathematically interpolated — you can transition opacity, not display (without extra help). When you hit any of these walls, that's your signal to move to keyframes.

Rule of thumb: if the element already has two CSS states, use transition. If it needs several beats, repeats, or runs on page load, use @keyframes.

On Your Portfolio

Transitions are the workhorse for interactive polish: project card lifts, link underline reveals, button states. They cost one line per element, need zero JavaScript, and degrade perfectly — if a browser ignores the transition, the user still gets the correct end state, just without the glide.
