The x.ai Hero: A 3D Flip-Up Reveal

Skill: reveal a headline word-by-word with depth — each word tipping and rising into place — using perspective and rotateX. This is the exact effect on x.ai's "Frontier AI models for everything you …" headline, rebuilt in pure CSS.

The Problem This Solves

A headline that just fades in, or even slides up a few pixels (the Lesson 1 rise), reads as flat — every pixel sits on the same plane, so motion happens but nothing feels physical. The premium "the words are settling into place" feel that studios like xAI ship comes from depth: each word starts tipped back in space and rotates upright toward you, as if printed on a card that flips flush to the page.

You cannot get that from translate and opacity alone — those live in the 2D plane. You need to rotate around an axis that points into the screen. And here's the catch that bites everyone the first time: rotating in 3D without telling the browser where the viewer's eye is produces a lifeless, squashed result that looks like a flat skew. Before CSS 3D transforms existed, this kind of motion meant canvas, WebGL, or a heavy JS library — overkill for a heading.

The Idea: Put An Eye In Front Of The Page

perspective is the missing piece. It answers one question: how far is the viewer's eye from the screen plane? A small value (300px) means the eye is close — rotations look dramatic, almost fisheye. A large value (2000px) means the eye is far — the same rotation looks subtle and calm. x.ai uses 1200px: present, but restrained.

Set it on the parent, not the words. One shared eye means every word rotates as if it belongs to the same physical surface — that coherence is the whole trick. Then each word's entry is just: start tipped back and dropped down, end upright and home.

The Recipe

.hero {
  perspective: 1200px;        /* eye distance, on the parent */
}
.hero .word {
  display: inline-block;      /* transforms need a block box */
}
@keyframes flip-up {
  from {
    opacity: 0;
    transform: translateY(45%) rotateX(-40deg);
  }
  to {
    opacity: 1;
    transform: translateY(0) rotateX(0);
  }
}
.hero .word {
  animation: flip-up 720ms cubic-bezier(.2,.72,.2,1) both;
  animation-delay: calc((sibling-index() - 1) * 90ms);
}

Reused the stagger is Lesson 1; the self-starting entry is Lesson 5. The only new primitive is perspective + rotateX.

The Boundaries

Perspective belongs on the parent. There is also a perspective() transform function you can put on the element itself, but then every element gets its own private vanishing point and the shared-surface coherence is lost. For a row of words, parent perspective is what you want; the function is for one-off isolated cards.

Don't over-rotate. Past roughly -55deg the text gets hard to read mid-flight and the effect tips from "polished" into "gimmick." This is decoration on top of content that must read instantly — when the motion competes with legibility, dial rotateX back toward -25deg or drop to the flat translateY rise.

Respect reduced motion. A spinning headline is exactly what prefers-reduced-motion exists to suppress; this lesson collapses the animation to near-instant in that mode (look at the stylesheet). Always pair entrance flourish with that guard.

CSS vs. JS stagger. x.ai ships this with framer-motion driving the per-word delay in JavaScript. That buys things CSS can't easily do — replaying on scroll-into-view, interrupting, sequencing with other timelines. But for a headline that animates once on load, sibling-index() does the same job with zero JS, which is exactly this workspace's goal. Reach for the library only when you need orchestration, not just timing.

On Your Portfolio

This is the move for the hero heading and section titles in this portfolio. Wrap each word of a heading in a <span class="word">, set perspective on the heading, and the whole thing reveals on load with depth — no animation library added to the bundle. Because the stagger is sibling-index()-driven, a longer or shorter heading just works; nothing is welded to a word count. If you want it to fire when the section scrolls into view rather than on load, swap the keyframe trigger for a scroll-triggered range from Lesson 9.
