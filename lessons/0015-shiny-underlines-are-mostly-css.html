Shiny Underlines Are Mostly CSS

Skill: keep decorative shimmer motion in CSS, and use React or Motion only to replay or mount it at the right time.

The problem it solves

It is tempting to put every animated detail of a Motion component into Motion props. That makes simple decorative effects harder to read. A gradient underline shimmer is not really a React lifecycle problem: it is a background image moving across a bar.

The only React-shaped requirement is replaying the shimmer when the word changes. CSS can draw and animate the bar. React can remount the inner span with a new key. Motion can optionally animate the underline growing in on first appearance.

The idea

A shimmer underline has two layers of ownership:

CSS owns the texture.

The underline is one wide linear gradient. Most of it is grey; the colored band sits in the middle. Moving background-position sends the band across the visible bar.

React owns the replay.

Changing a React key remounts the inner element, so the CSS animation starts again without manual timer code.

Motion owns the entrance.

If the underline should grow from zero on mount, a tiny scaleX animation is appropriate because it belongs to the component's first render.

Could CSS do it?

discover

Yes. The shimmer itself is a perfect CSS keyframe. CSS becomes awkward only when the replay must line up with a React word index. That is why the component keeps @keyframes hero-underline-shimmer in global CSS but passes replayKey={index} from the word rotator.

How the shimmer is built

The underline is a clipped bar.

The outer element is absolutely positioned under the word with left: 0 and right: 0. It inherits the word slot width, so when the rotating word gets wider or narrower, the underline follows.

The gradient is wider than the bar.

background-size: 400% 100% means the full gradient image is four times wider than the visible underline. The bar is only a window looking at part of that gradient.

Most of the gradient is grey.

The colored stops occupy only the middle of the gradient. The start and end are grey, so the underline reads as a calm grey rule except while the colored band passes through.

The animation moves the window.

The keyframe changes background-position from 100% 50% to 0% 50%. Nothing in the DOM moves. Only the visible slice of the oversized background changes.

The React key restarts the CSS clock.

CSS animations start when an element is created. When React renders <span key={index} /> with a new key, React replaces that inner span, so the CSS animation starts from the beginning again.

Motion only grows the container.

The outer motion.span can animate scaleX from 0 to 1 on first mount. It does not need to know anything about gradient stops or background position.

The production underline uses background-size: 400% 100%, so the gradient image is four underline-widths wide. The element clips that huge image to one visible bar. Animating background-position from 100% 50% to 0% 50% slides which part of the wide gradient sits inside the bar, which is how the colored band can enter, cross, and leave without moving the element itself.

.underline::after {
  background-image: linear-gradient(90deg, grey 0 35%, indigo 40%, pink 50%, gold 60%, grey 65% 100%);
  background-size: 400% 100%;
  animation: shimmer 1.5s linear;
}

@keyframes shimmer {
  from { background-position: 100% 50%; }
  to { background-position: 0% 50%; }
}

Practice

Scenario: the underline should shimmer once every time the rotating word changes. Which part should trigger the replay?

Code pattern

@keyframes hero-underline-shimmer {
  from { background-position: 100% 50%; }
  to { background-position: 0% 50%; }
}

function ShinyUnderline({ replayKey }) {
  return (
    <motion.span animate={{ scaleX: 1, opacity: 1 }}>
      <span
        key={replayKey}
        style={{ animation: "hero-underline-shimmer 1.5s linear" }}
      />
    </motion.span>
  );
}

Boundaries

  • Use CSS for the gradient and background-position animation. It is shorter, portable, and easy to disable with prefers-reduced-motion.
  • Use React keys when an animation should replay because component data changed.
  • Use Motion for the underline's mount reveal only if it is part of the component choreography.
  • Do not hard-code shimmer delays to match a word timer. That couples two separate clocks and will drift when props change.

Mission tie-in

The portfolio's ShinyUnderline is now a separate component because this effect is reusable beyond headlines. The lesson is the ownership rule: CSS paints and moves the shine; React decides when the shine should replay.
