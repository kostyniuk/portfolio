Capstone: The Dynamic Hero

Skill: take the recreated x.ai hero the last mile — make the underline resize to each word as it rotates, and replay the colour shimmer on every swap. These two behaviours are why x.ai reaches for JavaScript, and why your portfolio now ships a React component instead of pure CSS for this one piece.

The Problem This Solves

The pure-CSS reel from Lesson 14 has two honest limitations. First, a vertical stack sizes to its widest word, so the underline is one fixed width — under "use" it overhangs, under "discover" it fits. Second, the shimmer is a one-shot entrance; once it has swept, swapping words doesn't make it sweep again. x.ai does neither: the bar snaps to the exact width of whatever word is showing, animating the resize, and the colour shoots across again every single time a new word arrives.

Both need something CSS can't express on its own. Resizing to arbitrary text means measuring that text — a runtime number. Replaying an animation on a discrete event means re-triggering it on demand. The moment your animation has to react to changing state or measured layout, you've crossed from "timing" (CSS's job) into "orchestration" (JavaScript's job). That line is the whole lesson.

The Idea: JS Owns State, The Layout System Tweens

You don't animate in JavaScript — you let JS change two things and let CSS/Motion do the actual motion:

1. Resize. On each word change, measure the new word's width and write it to the box. A CSS transition: width (or Motion's layout) turns that number change into a smooth resize. The underline spans the box, so it follows for free.

2. Replay. Re-trigger the shimmer by remounting the element — in vanilla JS, remove the animation class, force a reflow, add it back; in React, change the element's key so it unmounts and remounts. A fresh element plays its animation from frame zero.

The Two Moves, In Code

// 1. resize: measure → write width → CSS transitions it
measure.textContent = nextWord;
rot.style.width = measure.offsetWidth + "px";

// 2. replay: restart the CSS animation
shine.classList.remove("run");
void shine.offsetWidth;        // force reflow
shine.classList.add("run");

React the same two ideas become <motion.span layout> for the resize and key={index} on the shimmer node for the replay — declarative versions of measure-and-write and remove-reflow-add.

What Shipped To The Portfolio

This is now a real component — components/animated-headline.tsx — built on Motion (already in the bundle, the same library x.ai uses). It composes all three techniques and adds the two dynamic moves declaratively:

// the rotating slot resizes via Motion's layout animation…
<motion.span layout transition={{ layout: { duration: 0.4 } }}>
  <AnimatePresence mode="popLayout">
    <motion.span key={word} …>{word}</motion.span>
  </AnimatePresence>

  // …and the shimmer replays because its key changes each word
  <span key={index} style={{ animation: "hero-underline-shimmer 1.4s linear" }} />
</motion.span>

It's live in two places: the About hero reads "Engineering things people love to build / design / ship / use", and a demo card sits on /my-components. The pure-CSS lessons stay true for the static case; the component is the dynamic upgrade, used precisely because the list rotates and the underline must fit each word.

The Boundaries

Don't reach for this by default. If your word list is fixed and the words are a similar length, Lesson 14's CSS reel is lighter and needs no JavaScript — prefer it. The JS version earns its keep only when you need per-word resize, replay-on-change, a data-driven list, or pausing on interaction.

Measure off-screen, not by thrashing. The demo keeps one hidden .measure span and reads offsetWidth once per change. Measuring forces layout, so do it once per swap, not per frame — and never inside an animation loop.

Reduced motion still wins. The component renders the settled state (no flip, no roll, no sweep) when prefers-reduced-motion is set; this demo disables its transitions the same way. Dynamic doesn't mean exempt.
