Rotating Words Need Lifecycle State

Skill: build a word-rotating component by separating three jobs: choose the current word, preserve the exiting word, and size the slot.

The problem it solves

A headline that swaps one word sounds like a CSS keyframe. For a fixed two-word demo, it can be. But a reusable React component receives arbitrary words, changes on a timer, and should let the old word slide out while the new word slides in.

React normally removes the previous keyed child immediately. CSS never gets a chance to animate it out, because the node is already gone. Motion's AnimatePresence fills that lifecycle gap: it lets a leaving child remain long enough to run its exit animation.

The idea

1. The timer chooses.

React state owns the current index: setIndex((i) => (i + 1) % words.length).

2. The key tells Motion what changed.

The visible word is keyed by text, so Motion can tell "this child is leaving, this one is entering."

3. The invisible spacer sizes the slot.

An invisible normal-flow span gives the line a baseline and a measurable width. The visible word can then be absolutely positioned and clipped.

What React normally does

React uses a child element's key to decide whether it is looking at the same child as before or a new child. If the key changes from "build" to "create", React treats that as "remove the old child, mount a new child."

That is correct for rendering, but bad for exit animation. A removed element cannot animate because it is no longer in the DOM. AnimatePresence is Motion's answer: it watches its direct children, notices when a keyed child is leaving, and keeps it mounted long enough for its exit prop to run.

Piece What it means in plain React What Motion adds
key={word} "This rendered child represents this exact word." Motion can tell which word is entering and which word is exiting.
initial No React equivalent. It is not state; it is an animation start style. The entering word starts below the slot at y: "100%".
animate The target visual state for the currently rendered child. The current word settles at y: "0%" and opacity 1.
exit React has already removed the child, so there is no place to put this. The leaving word moves upward to y: "-100%" before removal.

Could CSS do it?

CSS can loopfake it

Plain CSS can animate a known list if you hard-code the words in markup and write a timeline for their positions. That is useful for decorative, fixed copy. It breaks down for a component whose words prop can be any length, whose width should resize to each word, and whose reduced-motion behavior should branch inside React.

Practice

Scenario: the word changes from build to create, but build disappears instantly instead of sliding out. Which missing piece explains it?

Code pattern

<span className="relative inline-block">
  <span ref={measureRef} aria-hidden className="invisible whitespace-nowrap">
    {word}
  </span>

  <span className="absolute inset-0 overflow-hidden">
    <AnimatePresence mode="popLayout" initial={false}>
      <motion.span
        key={word}
        initial={{ y: "100%", opacity: 0 }}
        animate={{ y: "0%", opacity: 1 }}
        exit={{ y: "-100%", opacity: 0 }}
      >
        {word}
      </motion.span>
    </AnimatePresence>
  </span>
</span>

How the component runs

The state chooses a word.

index starts at 0, so word = words[0]. The timer later calls setIndex, which causes React to render with a different word.

The invisible span creates the real line box.

The spacer is normal text in normal flow, just invisible. That means it gives the slot a baseline and measurable width. The visible animated word is absolutely positioned on top of that stable space.

The measured width animates the container.

When the word changes, measureRef.current.offsetWidth reads the new spacer width. The wrapper's inline width changes, and CSS transitions that width so the underline and word slot resize smoothly.

The key changes, so presence starts.

When key={word} changes, AnimatePresence keeps the old word alive for its exit animation while the new keyed word enters.

The overflow clip hides the travel.

The visible word moves from below to center, and the old word moves from center to above. The wrapper uses overflow:hidden so you only see the word while it is inside the slot.

Reduced motion removes the timer.

If the user prefers reduced motion, the component does not start the interval and the Motion props skip sliding. This is calmer than merely making the slide faster.

Boundaries

  • Use CSS keyframes for fixed marketing copy with known words and no runtime measurement.
  • Use Motion for reusable React word rotators, because React owns the list, timer, keys, and reduced-motion branch.
  • Measure only the thing CSS cannot know. The invisible spacer is enough; the rest can stay declarative.
  • Respect reduced motion by disabling the timer or rendering the settled word. Motion's useReducedMotion() belongs close to the component that starts the motion.

Mission tie-in

The portfolio headline now has a reusable RotateWord piece. This lesson gives you the debug model: if a word swap looks wrong, ask whether the bug is in the timer, the keyed presence layer, or the measured slot.
